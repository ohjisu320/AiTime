## 2. Multi-Trial 시각화 개선 논의

### 현재 문제점
1. **`analyze_multi_trial()`은 있지만 시각화가 전혀 연결되지 않음**
2. **영상 분할 없이 전체 영상을 3번 반복 분석**
   - 같은 영상을 clapping, hurray, throwing으로 3번 처리
   - 구간 구분 없이 동일 영상에 대한 3가지 기준 비교만 수행
3. **타이밍이 전부 하드코딩됨**
   ```python
   parent_start = (trial_idx - 1) * 10.0   # 임시: 10초 간격
   parent_end = parent_start + 3.0
   ```
4. **시각화 파라미터가 아예 없음**

### 필요한 시각화 요소
| 요소 | 설명 |
|------|------|
| **구간 표시 바** | 영상 상단에 Trial 1/2/3 구간을 색상으로 표시 |
| **현재 Trial 정보** | 현재 분석 중인 동작(clapping/hurray/...) 표시 |
| **구간별 PASS/FAIL** | 각 Trial의 유사도 점수 + 통과 여부 |
| **부모/아이 동작 시작점** | 구간 내 부모 시작 → 아이 반응 시작 하이라이트 |
| **누적 ADOS 점수** | 현재까지의 A8/B18/B6 상태 |

### 개선 우선순위
1. ✅ 영상 구간 분할 (또는 BE에서 구간 정보 받기)
2. ✅ 구간별 `analyze()` 호출하도록 수정
3. ✅ 구간별 시각화 + 통합 디버그 영상 생성

## 4. 점프 감지 로직 개선

### 기존 문제
- Duration threshold 임계값 조정 필요
- 엉덩이 상승만으로 점프 감지 (단일 지표)

### 임계값 위치
```python
# analyzer.py 83번째 줄
DEFAULT_DURATION_THRESHOLD = 0.5  # 동작 지속 판정 기본 임계값
```
- 값을 높이면 (예: 0.6 또는 0.65) 더 정확한 동작 구간만 카운트

### 개선된 점프 감지 방법
기존의 엉덩이 상승 외에 **발목 감지** 추가:

1. **발목(ankle) 상승** ⭐ (메인 감지 방법)
   - 발이 땅에서 떨어질 때 발목 y좌표 변화
   - 점프 시 발이 먼저 땅에서 떨어지므로 더 정확
   
2. **엉덩이(hip) 상승** (보조 감지 방법)
   - 기존 방식 유지
   - 발목으로 감지 안 되면 엉덩이로 체크

**구현 내용**:
- Baseline 계산: 초기 3~5프레임에서 발목과 엉덩이 평균 위치 계산
- 발목 우선 감지 후 엉덩이 보조 감지
- 디버그 로그에 어떤 방법으로 감지됐는지 표시

## 5. 발차기 감지 로직 개선 시도

### 첫 번째 시도 (실패)

#### 문제 인식
- 엄마가 무릎 꿇은 상태에서 시작하면 발차기 감지 안 됨
- 기존: 양쪽 발목의 절대 높이 차이만 체크
- 무릎 꿇은 상태에서는 이미 한쪽 발이 낮아 감지 어려움

#### 개선 시도
1. **Baseline 대비 상대적 변화** - 초기 자세 대비 상승량
2. **무릎 각도 변화** - 다리를 펴는 동작 감지
3. **발-엉덩이 거리 증가** - 다리가 앞/옆으로 뻗어질 때

### 두 번째 문제 발견

#### 실제 문제
> "무릎꿇은 자세에서 조금만 발을 뻗으면 발차기로 인식해서 문제"
> "원래는 엄마 시간만 약간 이르게 탐지했는데, 이제는 아이도 이상해짐"

- 개선 후 오히려 **정확도가 더 낮아짐**
- 엄마: 이전에는 시간만 이르게 탐지 → 현재 상태 불명
- 아이: 이전에는 정상 → 현재 오탐지 발생

### 결론
- 기존 로직으로 복귀 후, threshold 조정하여 만족스러운 결과 얻음.

## 7. Attention Ratio 로직 확인

### 현재 구현

#### 계산 방법 (`_calculate_validity` 함수)
```python
def _calculate_validity(self, sequence: np.ndarray) -> float:
    """
    평균 키포인트 신뢰도를 기반으로 합니다.
    
    Args:
        sequence: 관절 시퀀스 (T, 17, 3)
    
    Returns:
        유효성 점수 (0~1)
    """
    scores = sequence[:, :, 2]  # 모든 프레임의 confidence score
    valid_scores = scores[scores > settings.MIN_KEYPOINT_SCORE]
    
    if len(valid_scores) == 0:
        return 0.0
    
    return float(np.mean(valid_scores))  # 평균 신뢰도 반환
```

#### 의미
- **아이의 포즈 키포인트 신뢰도 평균값**
- 높을수록 = 아이가 잘 감지되고 추적됨 = 주의/상호작용이 좋음
- 범위: 0.0 ~ 1.0

#### 사용 위치
- Trial 분석 시 `single_result.validity`로 저장
- 시각화에서 `Attention: XX%`로 표시
- 0.7 이상이면 초록색, 미만이면 주황색 표시

### 문제점
현재는 **단순히 키포인트 신뢰도 평균**만 사용

실제 "주의/상호작용"을 측정하려면 추가 요소 필요:
- 아이가 부모를 바라보는지 (얼굴 방향)
- 아이가 움직이는지 (동작 활성도)
- 부모-아이 거리/위치 관계

### 결론
🔄 **현재 로직 유지** (개선 보류)
