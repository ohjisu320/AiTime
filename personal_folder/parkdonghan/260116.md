## 오늘 한 일 정리

### 1) 컨설턴트님 피드백 정리 (오늘의 가장 귀중했던 순간)

* **서비스 이름(네이밍) 피드백**을 받음

  * “보조”라는 단어가 우리가 가진 히스토리/무게를 축소시킬 수 있다는 지적을 통해 **제목의 중요성**을 체감함.
* 병원 방문 경험을 이야기하는 과정에서

  * “교육생이면 안 된다”는 말을 들었을 때 **왜인지 되묻지 못한 태도**를 돌아봄
  * 컨설턴트님이 “왜 그런지 물어봤냐”고 하신 말에 뜨끔했고, 이것이 **간절함/집요함의 부족**일 수 있다고 느꼈음.
* 앞으로 프로젝트의 당락은

  * 회피하지 않고 **정면으로 부딪혀 설득해내는 배포**, **간절함**, **열정**에 달려 있다고 생각함.
* 컨설턴트님이 들려주신 사례들(부울경 학생들의 야구장 프로젝트, 야학당 프로젝트)을 통해

  * **진심으로 몰입하는 태도**
  * **되는 방법을 끝까지 찾는 집요함**
  * **클라이언트의 말을 끝까지 듣는 중요성(섣부른 판단 금지)** 을 다시 새김.
* 개발 중 흔들리지 않으려면 **기획 단계에서 ‘왜 하는지’ 비전이 명확해야 한다**는 메시지를 얻음.
* 이 팀/이 프로젝트/이 멘토들과 함께하는 지금의 경험을 **인생에 기록하고 싶은 뜨거운 프로젝트로 남기고 싶다**는 마음을 정리함.
* 그리고 나도 자신있게 나는 설계와 개발에 자신있다고 말할 수 있는 사람이 되고 싶다

* 팀원 모두가 “매우 우수”를 받길 바랐지만

  * 팀원들에게 **미안함**을 느낌.

# 2) 로컬 Docker Registry 띄우기

```powershell
docker run -d --name local-registry --restart unless-stopped -p 5000:5000 registry:2
```

확인:

```powershell
curl http://localhost:5000/v2/_catalog
```

## 1) `docker run`

* **컨테이너를 새로 만들어서 실행**하는 명령

## 2) `-d` (detached)

* **백그라운드로 실행**하라는 뜻.

## 3) `--name local-registry`

* 컨테이너 이름을 `local-registry`로 지정.

## 4) `--restart unless-stopped`

* Docker 데몬이 재시작되면 컨테이너도 자동으로 다시 켜지게 함.
* 단, 내가 명시적으로 `docker stop local-registry`로 꺼두면 그때는 자동 재시작 안 함.

## 5) `-p 5000:5000`

* 포트 매핑(포트 포워딩)
* 형식은 **`호스트포트:컨테이너포트`**
* 즉:

  * 내 PC의 `localhost:5000`으로 들어오면
  * 컨테이너 내부의 `5000` 포트로 전달됨
* 그래서 레지스트리에 `localhost:5000/v2/...`로 접근 가능

## 6) `registry:2`

* 실행할 **이미지 이름**.
* `registry`라는 이미지의 **태그(tag) `2`** 버전.
* Docker Hub의 “Docker Registry(이미지 저장 서버)” 공식 이미지로, 이게 실제 레지스트리 프로그램을 담고 있음.

build-agent:
```docker
# Jenkins 에이전트 기본 이미지.
# - JNLP(inbound agent) 방식으로 Jenkins Controller에 붙는 데 필요한 구성(에이전트 런타임 = 에이전트가 Jenkins 일을 수행하는 데 필요한 기본 도구 세트)이 들어있음
# SSH Agent 방식도 있다고 한다. 아마 이론 공부하면서 SSH로 접속한다는 게 이쪽 내용인 것 같다.
# 에이전트가 NAT/방화벽 뒤에 있어도, “밖으로 나가는 연결”은 대체로 허용되니까 붙기 쉽다. 웹 접속/업데이트/클라우드 사용 때문에 열어두니까.
# 이건 webrtc에서도 비슷한 내용이 있었던 거 같다.

# - latest-jdk17: JDK 17이 포함되어 있어 Jenkins Pipeline 실행/도구 호환에 유리
# 자바 진영에서 출발한 CI 서버이고
# 분산 실행(컨트롤러-에이전트) + remoting이 자바로 구현
# JVM 기반 플러그인으로 기능이 붙는 구조
# 그리고 17이 거의 표준
FROM jenkins/inbound-agent:latest-jdk17

# 패키지 설치(apt), 파일 권한 변경 등을 하려면 root 권한이 필요
USER root

# ----------------------------
# 1) 기본 유틸 + Python 도구 설치
# ----------------------------
# GPG = 전자 서명(서명/검증) 도구(진짜 docker에서 만든 건지 확인)
RUN apt-get update && apt-get install -y --no-install-recommends \
    # HTTPS로 패키지/키를 받기 위해 필요한 인증서 번들
    ca-certificates \
    # docker gpg key / 파일 다운로드에 사용
    curl \
    # GPG 키를 처리(검증/변환)하기 위한 도구
    gnupg \
    git \
    python3 \
    python3-pip \
    # PEP668(시스템 파이썬 pip 제한) 회피에 필수
    python3-venv \
 # 이미지 용량 줄이기: apt 캐시/리스트 삭제
 && rm -rf /var/lib/apt/lists/*

# -------------------------------------------
# 2) Docker "공식" repo 추가 + 최신 Docker CLI 설치
# -------------------------------------------
# 왜 공식 repo?
# - Debian 기본 docker.io 패키지는 버전이 낮을 수 있음
# /etc/apt/keyrings : apt가 저장소 키(공개키)를 보관하는 표준 위치
RUN install -m 0755 -d /etc/apt/keyrings && \
    # Docker 공식 GPG 키를 받아서 apt용 키 파일로 저장한다.(신뢰할 수 있는 패키지인지 확인용)
    # -f 실패 시 에러(404면 바로 실패)
    # -sS 조용히 하되 에러는 보여줌
    # -L 리다이렉트 따라감
    # gpg --dearmor : docker가 제공하는 키가 “텍스트(ASCII armor)” 형태일 수 있는데 apt가 쓰기 좋은 바이너리 keyring 형태로 변환하는 작업
    # -o .../docker.gpg : 변환 결과를 파일로 저장
    curl -fsSL https://download.docker.com/linux/debian/gpg \
      | gpg --dearmor -o /etc/apt/keyrings/docker.gpg && \
    # keyring 파일은 apt가 읽을 수 있어야 함
    chmod a+r /etc/apt/keyrings/docker.gpg && \
    # 현재 OS 정보 로드 (VERSION_CODENAME 같은 값 얻기 위해)
    # /etc/os-release에는 OS 정보
    # VERSION_CODENAME(예: bullseye, bookworm)
    # 우분투의 jammy, focal 같은 것
    . /etc/os-release && \
    # Docker 공식 apt 저장소를 sources.list에 추가
    # - arch: 현재 CPU 아키텍처(amd64 등) 자동
    # - signed-by: 위에서 만든 docker.gpg 키로 서명 검증(이 키로 검증하라)
    # ${VERSION_CODENAME} 내 OS 버전에 맞는 Docker 저장소 경로를 사용
    # stable 안정 채널
    echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
    https://download.docker.com/linux/debian ${VERSION_CODENAME} stable" \
      > /etc/apt/sources.list.d/docker.list && \
    # 새 repo 추가했으니 다시 인덱스 업데이트
    apt-get update && \
    # Docker CLI만 설치 (데몬은 호스트(Docker Desktop)에서 돌고, 우리는 sock로 붙을 거라서 CLI만 필요)
    # 데몬은 vm이나 백그라운드에서 돌고 있고
    # 명령은 CLI로 진행하며
    # 이때 통신은 docker.sock으로 이루어지는 것
    # - docker-ce-cli: docker 명령어 본체
    # - docker-buildx-plugin: buildx(멀티플랫폼/캐시 등) 지원
    # - docker-compose-plugin: docker compose v2 지원
    apt-get install -y --no-install-recommends \
      docker-ce-cli docker-buildx-plugin docker-compose-plugin && \
    # 이미지 슬림화
    rm -rf /var/lib/apt/lists/*

# 보안/원칙: 평상시 실행은 root가 아니라 jenkins 유저로
# (실제로 docker.sock 접근 때문에 run 때 --user root로 띄우기도 했지만,
#  기본 이미지 자체는 최소권한으로 두는 게 바람직)
USER jenkins


```

## docker build
- dockerfile을 읽어서 거기에 적힌 `RUN / COPY / ENV ...` 같은 명령대로 새 Docker 이미지(=컨테이너의 ‘설치 완료된 스냅샷’) 를 만드는 작업

-t는 태그(tag) 붙이는 것.

## -f agents/images/Dockerfile.build (Dockerfile 경로 지정)

-f는 어떤 Dockerfile로 빌드할지를 지정.

# 8) Pipeline Script

```groovy
pipeline {
  agent none
  options { disableConcurrentBuilds() }

  environment {
    APP_NAME  = "fastapi-app"
    REGISTRY  = "localhost:5000"
    IMAGE_TAG = "local-${BUILD_NUMBER}"
    IMAGE_URI = "${REGISTRY}/${APP_NAME}:${IMAGE_TAG}"

    SOURCE_DIR = "/src/fastapi-app"  // 여기엔 쓰지 않음(읽기만)
    HOST_BASE  = "http://host.docker.internal:8000"
  }

  stages {
    stage("CI: Lint & Test") {
      agent { label "build && docker" }
      steps {
        deleteDir()
        sh '''
          set -e
          cp -a ${SOURCE_DIR}/. .
        
          python3 -m venv .venv
          . .venv/bin/activate
        
          pip install -U pip
          pip install -r requirements.txt -r requirements-dev.txt
        
          ruff check .
          PYTHONPATH=. pytest -q
        '''

      }
    }

    stage("Build & Push (Local Registry)") {
      agent { label "build && docker" }
      steps {
        deleteDir()
        sh '''
          set -e
          cp -a ${SOURCE_DIR}/. .
          docker build -t ${IMAGE_URI} .
          docker push ${IMAGE_URI}
        '''
      }
    }

    stage("Deploy (Local Docker)") {
      agent { label "deploy" }
      steps {
        sh '''
          set -e
          docker pull ${IMAGE_URI}
          docker rm -f fastapi-app 2>/dev/null || true
          docker run -d --name fastapi-app --restart unless-stopped \
            -p 8000:8000 ${IMAGE_URI}
        '''
      }
    }


    stage("Verify (health/smoke)") {
      agent { label "deploy" }
      steps {
        sh '''
          set -e
          curl -fsS ${HOST_BASE}/health
          curl -fsS -X POST ${HOST_BASE}/predict \
            -H "Content-Type: application/json" \
            -d '{"text":"good"}' > /dev/null
        '''
      }
    }
  }
}

```
